Part 1 How Data Moves: The Request Lifecycle (From Front to Back)

🏦 Real-Life Analogy: Visiting a High-Security Luxury Bank
Imagine you want to deposit money into a secure bank vault. You don't just jump straight into the vault! You walk through the entrance doors, get checked by security guards, fill out a deposit slip at the inspection counter, hand it to the teller, and the teller deposits your cash into the vault.

Below is the exact order of how folders and code execute when a user clicks a button in React before anything touches the Neon PostgreSQL database:

1
HTTP Request
🚶 Customer visits the bank
The React frontend sends a network request, e.g. POST /api/v1/auth/register with user info.
▼
2
Routes (routes/api.php)
🚪 Front Entrance Doors
Directs the URL to the right department. Tells Laravel: "Send registration requests to AuthController."
▼
3
Middleware
🛡️ Security Guard / Bouncer
Sanctum Middleware: Checks if the user is authorized. If it's a private page and you aren't logged in, it blocks you (401).
▼
4

📋 Inspection Desk
app/Http/Requests/: Validates data format (e.g. Is email valid? Password ≥ 8 characters?). If invalid, rejects with 422.
▼
5

💁 Front-Desk Receptionist
app/Http/Controllers/: Receives clean, validated data. Coordinates what actions to take and returns the JSON response.
▼
6

⚙️ Back-Office Specialist

🏦 The Bank Vault
Neon PostgreSQL: The permanent, cloud-hosted storage where users and tasks actually live.

Part 2 What We Built (In Chronological Order)

Here is our complete development journey from zero to production deployment:

1. The Database Foundation Foundation

Why first: You cannot save users or tasks without a place to put them! We created migration blueprints for users, tasks, and verification_codes, then safely migrated them to Neon PostgreSQL in the cloud.

2. User Input Validation Gatekeeper

Files: RegisterRequest.php, LoginRequest.php.
Validated names, unique emails, and strong password rules (mixed case, numbers, symbols) before any code touches the database.

3. The 6-Digit Email Code Engine Security

Files: VerificationCodeService.php, VerificationCodeMail.php.
Generates secure 6-digit codes. Never saves plaintext codes—only secure SHA-256 hashes with 15-minute expiration and max 5 attempts.

4. Full Authentication Lifecycle Auth

File: AuthController.php.
Built Sign Up, Email Verification, Login (strictly blocks unverified users), Logout (invalidates sessions), and Password Reset.

5. Task Management Engine Tasks

File: TaskController.php.
CRUD for tasks: Create, View, Update, Delete, Mark Completed (with server timestamp), Cancel with reason, and Reopen back to pending.

6. Dashboard & Analytics Metrics

File: DashboardController.php.
Calculates live metrics for the user: Total tasks due today, completed today, pending/overdue actions, and today's timeline.

7. Timezone & Google SMTP Production

Configured Asia/Manila (UTC+8) so task dates match local Philippine time. Linked live Google SMTP to deliver actual emails to inboxes.

8. Automated 30-Min Reminders Scheduler

Files: SendTaskReminders.php, TaskReminderMail.php.
Background scheduler checks every minute and automatically emails users 30 minutes before their task is due.

9. Automated Test Suite Testing

Wrote 22 Pest automated tests covering every feature (auth, emails, task isolation, reopen). All 22 pass with 72 assertions in 0.8s.

10. Cloud Deployment on Render Cloud Live

Built a production Dockerfile with PHP 8.4 + Apache. Configured lightweight health checks for cron-job.org to prevent sleep 24/7.
